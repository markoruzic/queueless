# 06 – Plan rada i zapisnik promjena

## 1. Svrha dokumenta

Ovaj dokument opisuje razvojni tijek projekta QueueLess, glavne faze rada i važne odluke donesene tijekom projekta. Dokument služi kao arhiva projektnih aktivnosti.

## 2. Kontekst razvoja

QueueLess je razvijen za TVZ Mc2 natjecanje. Primarni cilj bio je osmisliti ideju, pripremiti poslovni model i razviti aplikacijski prototip koji se može prezentirati.

Nakon završetka natjecanja projekt je dokumentiran za kolegij Projektno razvijanje programske podrške.

## 3. Faze razvoja

### Faza 1: Definiranje problema
Identificiran je problem čekanja u redovima i nedostatka informacija o gužvi prije dolaska na lokaciju.

### Faza 2: Definiranje rješenja
Oblikovana je ideja aplikacije QueueLess i definirane su osnovne funkcionalnosti: karta, status gužve, procjena čekanja i korisnički unos.

### Faza 3: Poslovni model
Razvijen je poslovni model s B2C i B2B elementima, mogućnostima promocije lokacija, partnerstvima i budućim monetizacijskim modelima.

### Faza 4: UI/UX i koncept sučelja
Razrađen je izgled aplikacije i korisnički tokovi s naglaskom na mobile-first korištenje.

### Faza 5: Implementacija aplikacije
Razvijen je React/Vite prototip aplikacije s glavnim stranicama, kartom, podacima o lokacijama i procjenom gužve/čekanja.

### Faza 6: Deploy i prezentacija
Aplikacija je postavljena na Vercel i pripremljena za prezentaciju preko browsera i mobilnog uređaja.

### Faza 7: Dokumentiranje projekta
Nakon natjecanja izrađena je projektna dokumentacija za kolegij.

## 4. Zapisnik odluka

| Faza | Odluka | Razlog |
|---|---|---|
| Početak projekta | Fokus na problem čekanja | Problem je čest i razumljiv |
| Razrada ideje | Aplikacija prikazuje gužvu i čekanje | To je glavna korisnička vrijednost |
| MVP | Karta, status, čekanje, crowd input | Najbolje prikazuje ideju |
| Razvoj | Odabran React/Vite | Brz razvoj frontend prototipa |
| Karta | Odabran Leaflet / React Leaflet | Prikladno za prikaz lokacija |
| Deploy | Odabran Vercel | Jednostavan javni deploy |
| Dokumentacija | Struktura prema predavanju | Potrebno za kolegij |

## 5. Upravljanje promjenama

Tijekom razvoja promjene su praćene kroz Git commitove u GitHub repozitoriju. Promjene su se odnosile na dodavanje stranica, uređivanje dizajna, dodavanje podataka, dodavanje karte, prilagodbu mobilnom prikazu, pripremu za deploy i dokumentiranje projekta.

## 6. Evidencija projektnih materijala

Tijekom projekta nastali su ideja aplikacije, poslovni plan, natjecateljska prezentacija, prezentacija poslovnog modela, izvorni kod aplikacije, Vercel deploy i projektna dokumentacija za kolegij.

## 7. Zaključak

Projekt QueueLess razvijen je kroz više faza: od ideje i poslovnog modela do funkcionalnog prototipa i dokumentacije. Iako je projekt primarno nastao za Mc2 natjecanje, sada je kroz dokumentaciju i GitHub repozitorij predstavljen kao cjelovit projekt razvoja programske podrške.
